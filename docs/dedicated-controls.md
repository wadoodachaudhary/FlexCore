# Dedicated FlexCore controls

The counterpart families selected from the parity backlog are implemented in the library and demonstrated at `/demo/counterparts` in FlexCore.Showcase. These controls reuse the existing dropdown, button, date picker, chart, tree grid, splitter, dialog, toolbar and result-card foundations. No host-level input, calendar, selector or modal implementation is required.

This closes the missing **dedicated component** entries in that selected group. It does not claim complete Telerik API or feature parity. The boundaries below are part of the public contract.

## Components and scope

| Family | Public controls | Implemented behavior |
| --- | --- | --- |
| Forms | `FormControl`, `FormItemControl`, `FormGroupControl`, `FormAutoGeneratedItemsControl` | Model or EditContext; scalar field generation; Display/Editable/DataAnnotations metadata; grouped columns; custom field and button templates; validated submission; invalid drafts retained. |
| Validation | `ValidationSummaryControl`, `ValidationMessageControl`, `ValidationTooltipControl` | EditContext-backed summary, per-field messages and focus/hover presentation. |
| Calendar | `CalendarControl` | Month/year/decade views; single, multiple and range selection; culture/first weekday; date bounds and disabled dates; day templates; arrow/Home/End/Page navigation. |
| Time | `TimePickerControl` | Editable clock-time dropdown, configurable interval and bounds, culture/format, parsing errors and form validation. DatePicker's time popup now uses this control. |
| Suggestions | `AutoCompleteControl<TItem>` | Local or asynchronous suggestions, cancellation, debounce, minimum text length, result limits, templates, keyboard selection and free-text commits. |
| Navigation | `StepperControl` | Wizard step descriptors, horizontal/vertical layout, linear or free navigation, disabled/invalid states, asynchronous veto and keyboard navigation. |
| Selection | `RadioGroupControl<TValue>`, `ToggleButtonControl` | Group binding and EditContext integration; native radio arrow behavior; two-way toggle state and accessible pressed semantics. |
| Colors | `ColorPaletteControl` | Configurable palette/columns/tile size, templates, selection and arrow navigation. Shares the original ColorPicker palette. |
| Gauges | `GaugeControl`, `ArcGaugeControl`, `CircularGaugeControl`, `LinearGaugeControl`, `RadialGaugeControl` | Shared chart renderer with configured limits, values, ranges, pointers, ticks, formats and value templates. |
| Financial charts | `StockChartControl` | Candlestick/OHLC/HighLow data, overview chart, date/index navigator, range events, zoom and pan. |
| Docking | `DockManagerControl` | Tab groups, nested splits, drag/drop or menu docking, floating/resizable dialogs, pin/unpin, close/reopen and validated JSON layout persistence. |
| Layout | `AppBarControl`, `GridLayoutControl`, `GridLayoutItemControl` | Toolbar sections; static/sticky/fixed positioning; arbitrary CSS grid tracks, spans, alignment and small-screen collapse. |
| Icons | `SvgIconControl`, `FontIconControl`, `FlexIcons` | Built-in vector path catalog, custom paths/fragments, CSS font classes or glyphs, size and accessible labels. |
| Prompt UI | `AIPromptControl` | Provider callback, suggestions, commands, response history, result-card actions, cancellation and error presentation. No provider credentials or network service is built in. |
| Gantt | `GanttControl` | Hierarchical task grid/timeline, task CRUD with drafts, progress, dependency lines, date validation, day/week/month/year scale, dragging/resizing and cancellable changes. |
| PDF | `PdfViewerControl` | Bytes/URL/file opening, paging, zoom, rotation, selectable text, search, download/print, AcroForm field editing, text notes and highlights saved into the PDF. |

## Host setup

Include the host application’s generated `{ApplicationAssembly}.styles.css` stylesheet; it imports the FlexCore scoped CSS, including the PDF text-selection layer. Continue loading `_content/FlexCore/fx-grid-core.css` for shared grid styling. The showcase demonstrates this setup.

## Forms and input binding

```razor
@using Fx.ControlKit

<FormControl Model="@record" Columns="2" OnValidSubmit="SaveAsync" />

<FormControl EditContext="@editContext" OnValidSubmit="SaveAsync">
    <ChildContent>
        <FormGroupControl Label="Details" Columns="2">
            <FormItemControl Field="Name" />
            <FormItemControl Field="Quantity" />
        </FormGroupControl>
        <FormItemControl Field="Notes" EditorType="FormEditorType.TextArea" />
        <ValidationTooltipControl Field="Name">Name validation</ValidationTooltipControl>
    </ChildContent>
</FormControl>
```

Supply `Model` **or** `EditContext`. `OnSubmit` runs before validation; `OnValidSubmit`/`OnInvalidSubmit` follow it. `OnUpdate` receives the root model, declared field path and committed value. `FormItemControl` supports dotted paths to already initialized nested models. Templates receive the field's owner/property and an awaited `SetValueAsync` callback. DataAnnotations validates using standard Blazor behavior; applications that need recursive object-graph validation supply it through `ValidatorTemplate`.

Automatic generation includes supported scalar public properties and honors `Display(AutoGenerateField=false)` and ordering. Complex values require an explicit template. Read-only properties stay disabled. Invalid numeric/date/time text remains visible and prevents submission; it is not replaced with zero or the previous display value. `PropertyGridControl` now uses the same field editors while preserving its existing custom-editor API.

```razor
<AutoCompleteControl TItem="Customer" DataSource="@customers"
    TextSelector="c => c.Name" @bind-Value="searchText"
    MinLength="2" DebounceDelay="250" MaxSuggestions="20" />
<TimePickerControl @bind-Value="appointment" Step="@TimeSpan.FromMinutes(15)" />
<RadioGroupControl TValue="string" Items="@choices" @bind-Value="choice" />
<CalendarControl SelectionMode="CalendarSelectionMode.Range" @bind-Range="range" />
```

Autocomplete publishes a string on selection/Enter/blur; `ItemSelected` additionally supplies a matched data item. `OnRead` can replace local filtering and receives a cancellation token. Stale results are discarded even when a provider ignores cancellation. TimePicker represents `TimeOnly?`, not a duration; bounds cannot cross midnight, and the chosen step must produce at most 1,441 choices.

## Charts, docking and Gantt

Gauge wrappers pass through to ChartControl's shared SVG renderer. `Min < Max` and finite values are required. Ranges and pointers are clipped to the configured domain. StockChart requires `ChartDataPoint.DateValue`; its existing financial `Value`/`Value2`/`Value3`/`Value4` mapping is open/high/low/close. `RangeChanged` reports navigator changes without mutating source data.

DockManager takes `DockPanel` definitions (key/title/content/permissions) separately from serializable `DockLayoutState`. `SaveLayout()` and `RestoreLayoutAsync(json)` persist tab membership, active tabs, split orientation/ratio, floating dimensions/position, hidden and closed panes. Restore rejects unknown/duplicate keys, invalid ratios and cycles. `DockAsync`, `FloatAsync`, `UnpinAsync` and `CloseAsync` offer the same operations programmatically. Floating positions are offsets from the centered dialog position. Docking re-creates content when it moves between groups; keep application data in the host model or a scoped service rather than transient component fields.

Gantt uses concrete `GanttTask` records that hosts can map to/from their domain model. IDs are stable strings. `ParentId` supplies hierarchy and `Predecessors` is a comma-separated set of task IDs. Dependencies are **finish-to-start**, without lag or automatic downstream rescheduling. Moves/resizes snap to whole days and preserve clock time; zero-duration tasks are displayed as narrow bars. Task dialog fields allow date-based edits. `TaskChanging` can veto a create/update/delete before `TasksChanged` publishes cloned data. Referenced tasks cannot be deleted until child/dependency links are removed. Resource leveling, baselines, critical-path calculation and other dependency types remain future feature work.

## PDF integration and boundaries

```razor
@using Fx.ControlKit.Pdf
<PdfViewerControl DocumentBytes="@pdfBytes" FileName="report.pdf"
                  Height="650px" AllowFormFilling="true" AllowAnnotations="true" />
```

Use `Url` instead of bytes for a browser-accessible PDF; normal CORS rules apply. Public methods include `OpenAsync`, `GoToPageAsync`, `SetZoomAsync`, `FindAsync`, `SaveAsync`, `DownloadAsync` and `PrintAsync`. `SaveAsync` streams the edited file back to .NET. `MaxFileSize` defaults to 50 MiB. The file picker also enforces that bound.

The viewer uses locally bundled [PDF.js](https://mozilla.github.io/pdf.js/examples/) for page rendering/text extraction and [PDF-Lib](https://pdf-lib.js.org/docs/api/classes/pdfform) for writing AcroForm values and annotations. Assets load lazily from `_content/FlexCore`; no CDN or remote document processor is involved. Licenses and pinned versions are recorded in `wwwroot/vendor/PDF-DEPENDENCIES.md`. Rendering requires browser canvas/workers; failures remain visible instead of silently switching to the browser PDF viewer.

Supported editing covers text, checkbox, single-choice dropdown/list/radio fields, text notes and highlights. Existing notes/highlights can be inspected; removal currently applies to annotations added in the current viewer session. Multiselect fields, signatures and other unsupported field types remain read-only. XFA and encrypted PDF editing are not supported. PDF-Lib's standard field appearance font cannot encode every Unicode character; unsupported values produce an error without committing the field. Rich drawing annotations, a thumbnails/bookmarks panel, redaction and general PDF page editing remain feature gaps. Printing uses the browser print service and its normal print dialog.

## Verification

From FlexCore:

```sh
dotnet run --project tests/FlexCore.RegressionTests
cd tests/FlexCore.Counterparts.BrowserTests
dotnet run
```

The browser fixture requires Python Playwright/Chromium and pypdf, and the sibling FlexCore.Showcase checkout. It links the real showcase page, starts an isolated loopback test server on an ephemeral port and shuts it down on completion. It does not start HomeFront or the user's showcase instance. Browser tests exercise typing, validation, suggestions, selection, docking, Gantt editing/dragging and PDF changes. An independent PDF reader checks saved field values and annotation dictionaries. `FLEXCORE_COUNTERPART_ONLY=PDF` limits a run to PDF interactions when working on that bridge.
